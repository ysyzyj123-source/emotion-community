## 一、环境搭建阶段

### 问题 1：Python 未真正安装，命令提示符找不到
- **现象**：`python --version` 无反应，`where python` 只找到 Microsoft Store 的占位符（0 字节假程序）。
- **原因**：Windows 的 Microsoft Store 会自动创建一个 `WindowsApps/python.exe` 假程序，用于引导用户去应用商店安装，并非真实 Python。
- **解决**：安装官方 Python 3.13，并勾选 "Add Python to PATH"。实际安装目录在 `C:\Users\<用户>\AppData\Local\Programs\Python\Python313\`。
- **教训**：判断 Python 是否可用不能只看 `where`，要实际运行并看版本；Store 占位符是常见坑。

### 问题 2：MySQL 已安装但服务未启动、命令找不到
- **现象**：`mysql --version` 报 "not recognized"，MySQL 服务状态为 "Stopped"。
- **原因**：MySQL 8.4 已安装（`C:\Program Files\MySQL\MySQL Server 8.4\`），但 bin 目录未加入 PATH，且 Windows 服务未启动。
- **解决**：
  - 启动服务：`net start MySQL`（需管理员权限）
  - 将 MySQL bin 目录加入用户级 PATH：`setx Path "原值;...\MySQL Server 8.4\bin"`
- **注意**：`setx` 写入注册表需要权限，普通终端可能报"注册表访问被拒"，需以管理员或完整权限执行。

### 问题 3：Git 推送 GitHub 失败（network 443 连不上）
- **现象**：`git push` 报 `Failed to connect to github.com port 443`，但 `ping github.com` 能通（106ms）。
- **原因**：系统开启了代理 `127.0.0.1:7897`（通常是 Clash/V2Ray 等代理软件），但代理软件当前未运行，导致 HTTPS 请求全部被拦截、连不上。
- **解决**：确认代理软件已启动，或临时关闭系统代理改用直连。关闭系统代理方式：
  ```powershell
  # 关闭
  Set-ItemProperty -Path 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' -Name ProxyEnable -Value 0
  # 恢复
  Set-ItemProperty -Path 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' -Name ProxyEnable -Value 1
  ```
- **教训**：GitHub 推送失败时，先检查系统代理是否开启且代理软件是否在运行；这是国内开发最常见的网络坑。

### 问题 4：pip 安装包失败（连不上代理端口 7897）
- **现象**：`pip install cryptography` 报 `HTTPSConnection(host='127.0.0.1', port=7897): Failed to establish a new connection`。
- **原因**：pip 走了系统代理 7897，但代理软件未运行。
- **解决**：临时关闭系统代理，或为 pip 指定国内镜像源（如清华源）绕过代理：
  ```powershell
  pip install cryptography -i https://pypi.tuna.tsinghua.edu.cn/simple
  ```
- **教训**：pip/网络类安装失败，优先检查代理；用国内镜像源可加速并避开代理问题。

### 问题 5：PyMySQL 连接 MySQL 8 报错 cryptography 缺失
- **现象**：后端启动报 `RuntimeError: 'cryptography' package is required for sha256_password or caching_sha2_password auth methods`。
- **原因**：MySQL 8 默认使用 `caching_sha2_password` 认证，PyMySQL 需要 `cryptography` 库做 RSA 加密握手。
- **解决**：`pip install cryptography`。
- **教训**：连接 MySQL 8 时务必安装 cryptography，否则认证失败。

### 问题 6：Python 虚拟环境 pip 引导失败（ensurepip）
- **现象**：`python -m venv` 建环境后，`pip --version` 报 "No module named pip"；`ensurepip` 报 `PermissionError`（临时目录 chmod 失败）。
- **原因**：受系统沙盒/权限限制，Python 3.13 的 ensurepip 在临时目录执行权限操作被拒。
- **解决**：用系统 Python 的 pip 配合 `--python` 参数引导到 venv，或在有完整权限的环境下执行 `ensurepip`。
- **教训**：venv 建好后先验证 pip；权限相关的临时目录问题可通过指定可写临时目录解决。

## 二、后端开发阶段

### 问题 7：Flask 配置导入路径错误 `ModuleNotFoundError`
- **现象**：后端启动报 `from .config import Config` → `ModuleNotFoundError: No module named 'app.config'`。
- **原因**：`config.py` 放在 backend 根目录，但 `app/__init__.py` 用了相对导入 `from .config import Config`（app 包内没有 config.py）。
- **解决**：改为 `from config import Config`（因为 backend 根目录在 sys.path 里）。
- **教训**：相对导入 vs 绝对导入要弄清楚配置文件的位置；配置文件在包外时用绝对导入。

### 问题 8：密码哈希过长导致数据库写入失败 `Data too long for column 'password'`
- **现象**：注册/种子脚本报 `DataError: (1406, "Data too long for column 'password' at row 1")`。
- **原因**：`werkzeug.security.generate_password_hash` 默认用 scrypt 算法，生成的哈希约 160+ 字符，超过 password 列的 `VARCHAR(128)`。
- **解决**：将 user/teacher/admin 表的 password 列改为 `VARCHAR(255)`（模型 + 数据库 ALTER 同步修改）。
- **教训**：密码哈希长度要预留，避免用 scrypt 等长哈希时截断。

### 问题 9：Flask 路由 endpoint 重复注册 `AssertionError`
- **现象**：启动报 `View function mapping is overwriting an existing endpoint function: dashboard.sentiment_trend`。
- **原因**：修改情感趋势接口时，旧函数体与新函数体并存，导致 `/sentiment-trend` 路由定义了两次、endpoint 名称冲突。
- **解决**：删除重复的函数定义，确保每个路由只注册一次。
- **教训**：改接口时用全局搜索确认没有残留的旧版本函数；同名 endpoint 会直接导致 Flask 启动失败。

### 问题 10：中文内容在终端显示乱码，导致测试误判
- **现象**：发帖测试时中文变成 `????` 或乱码，导致某些测试结果看起来错误（如"7个汉字昵称"被误判通过、登录失败等）。
- **原因**：PowerShell 命令行直接发送中文时，编码（非 UTF-8）导致后端收到乱码文本。
- **解决**：改用 Python 的 `requests` 库发送（默认 UTF-8），或正确设置请求编码，就能得到准确结果。
- **教训**：在 Windows PowerShell/终端里直接传中文进行接口测试极易乱码，应使用脚本（Python requests）确保编码正确。

## 三、前端开发阶段

### 问题 11：npm 幂等脚本被 PowerShell 拦截
- **现象**：`npm -v` 报 `File D:\npm.ps1 cannot be loaded because running scripts is disabled`。
- **原因**：Windows PowerShell 默认执行策略禁止运行脚本（`npm.ps1` 是脚本）。
- **解决**：用 `npm.cmd` 代替 `npm`（cmd 版本不受执行策略限制），或临时放行执行策略。
- **教训**：Windows 下 npm 用 `npm.cmd` 调用更稳妥。

### 问题 12：echarts 打包体积过大警告
- **现象**：`vite build` 提示 `Some chunks are larger than 500 kB`。
- **原因**：echarts 库本身较大。
- **解决**：不影响功能，可忽略；如需优化可用按需引入或代码分割。
- **教训**：毕设演示不影响，不必过度优化。

## 四、BERT 情感分析阶段

### 问题 13：transformers 5.x 参数名变更导致 TrainingArguments 报错
- **现象**：训练脚本报 `TypeError: TrainingArguments.__init__() got an unexpected keyword argument 'evaluation_strategy'`，后又报 `'logging_dir'`。
- **原因**：transformers 5.x 将 `evaluation_strategy` 改名为 `eval_strategy`，并移除了 `logging_dir`。
- **解决**：改用 `eval_strategy="epoch"`，移除 `logging_dir`；并安装 `accelerate`（Trainer 需要）。
- **教训**：大库版本升级常有参数名变更，报错时对照当前版本文档调整；`pip install accelerate` 是 Trainer 必需依赖。

### 问题 14：BERT 预训练模型加载警告（missing/unexpected keys）
- **现象**：加载模型时报大量 `UNEXPECTED`/`MISSING` 提示（bert.embeddings.LayerNorm 等）。
- **原因**：这是正常的——BERT 预训练权重是掩码语言模型头，转成分类任务时分类头参数是新建的（MISSING），LayerNorm 参数命名差异（beta/gamma vs weight/bias）为 UNEXPECTED。
- **解决**：这些是加载警告，不影响训练与推理，可忽略。
- **教训**：转换模型用途时，头部的 UNEXPECTED/MISSING 提示是预期行为，不必担心。

### 问题 15：推理服务缺 flask 模块
- **现象**：BERT 服务启动报 `ModuleNotFoundError: No module named 'flask'`。
- **原因**：ML 独立环境（`ml/.venv`）与后端环境隔离，没装 flask。
- **解决**：在 ML 环境单独 `pip install flask`。
- **教训**：独立虚拟环境需各自安装所需依赖，不能假设共享。

### 问题 16：BERT 推理服务对校园文本判定偏差
- **现象**：公开数据集（ChnSentiCorp，商业评论）训练出的模型，把"考研通过今天开心幸福"误判为负向。
- **原因**：公开数据集是商品评论情感，没有校园场景语料，模型不懂"考研上岸""期末考试"等校园表达。
- **解决**：用 AI 生成校园语料（学业/情感/求职/生活 + 高危描述）二次微调 BERT，得到"校园微调版"，正确识别校园表达。
- **教训**：通用/公开数据集迁移到特定领域（校园）会有明显偏差，需领域语料二次微调，这正是任务书"用校园语料微调"的意义。

### 问题 17：BERT 推理后缺少紧急程度字段，预警不触发
- **现象**：发帖后 `emergency=None`、`warning=False`，高危内容没预警。
- **原因**：BERT 只输出正/负分类，推理服务没返回紧急程度字段，后端取不到 `emergency`。
- **解决**：在推理服务增加 `compute_emergency`（BERT 情感 + 高危关键词规则组合），命中自伤类词判紧急。
- **教训**：模型输出与业务字段要对齐；紧急程度可作为独立任务或规则补充，后续可训练专门分类头。

### 问题 18：Python 3.13 下 torch/深度学习库兼容性
- **现象**：部分深度学习库在 Python 3.13 下可能滞后（torch 安装源只有部分版本）。
- **应对**：选用兼容当前 Python 版本的 torch（如 2.11.0+cu128），并确认 GPU CUDA 匹配（RTX 5070 Ti，CUDA 13.4 驱动，装 cu128 版 torch）。
- **教训**：新显卡/新 Python 需确认深度学习框架的 CUDA 版本匹配，避免装错版本。

## 五、LDA 主题模型阶段

### 问题 19：LDA 训练爆内存
- **现象**：LDA 训练过程中内存耗尽、程序中断。
- **原因**（排查后确认）：
  1. 使用 `CoherenceModel` 且 `coherence="c_v"` —— c_v 需要构建大型共现统计，内存开销大；
  2. 在循环里对 2/3/4/5/6 五个主题数各训练一次 LDA 并各算一次 c_v，内存峰值累积；
  3. `passes=20` + `alpha="auto"` + `eta="auto"` 进一步增加开销。
- **关键结论**：本不该爆 —— 机器有 20GB 可用内存，60 条短文本的 LDA 正常只需几百 MB。爆内存是脚本配置激进导致。
- **解决**：改为**内存安全配置**：
  - 放弃 c_v，直接固定 4 主题（对应学业/情感/求职/生活）；
  - passes 降到 8；
  - 去掉 `alpha/eta="auto"`。
  - 训练秒级完成，不占内存。
- **教训**：LDA/c_v 一致性计算是大内存消耗点；固定主题数 + 低 passes 既满足需求又不爆内存。**遇到"爆内存"先看脚本配置，不是机器或模型本身的问题**。

### 问题 20：LDA 推理服务返回 `float32` 无法 JSON 序列化
- **现象**：`/predict` 返回 500，日志报 `TypeError: Object of type float32 is not JSON serializable`。
- **原因**：gensim LDA 返回的主题概率是 numpy.float32，Flask 的 jsonify 无法序列化。
- **解决**：把概率显式转成 Python `float()`：`topic_dist = {str(t): float(round(p, 4)) for t, p in dist}`。
- **教训**：numpy 标量（float32）不能直接交给 Flask jsonify，需转成标准 float。

### 问题 21：LDA 推理对某些短文本概率为 0、归类默认
- **现象**：个别帖子话题 `prob=0.0`，归到默认板块。
- **原因**：语料较小（60条），部分词不在词典中，分词后词袋为空。
- **解决**：可接受（有默认板块兜底）；后续扩充语料可提升覆盖率。
- **教训**：语料规模影响模型覆盖面，小语料会有未见词；设置默认归类保证系统不中断。

## 六、模型与文件管理

### 问题 22：模型权重误加入 Git 仓库
- **现象**：`git status` 发现 `model.safetensors`（数百 MB）被暂存。
- **原因**：`.gitignore` 原本只忽略 `*.pt/*.pth/*.bin/*.onnx`，未覆盖 `.safetensors`（transformers 5.x 默认保存格式），导致模型权重被加入。
- **解决**：
  - `git reset` 取消暂存模型权重；
  - 在 `.gitignore` 增加 `*.safetensors` 及 `ml/data/models/`、`ml/data/*/processed/` 等目录；
  - 后续代码、训练脚本入库，模型权重留本地。
- **教训**：模型权重文件大，不应提交 GitHub；.gitignore 要覆盖当前框架的权重扩展名（safetensors），并忽略模型目录。

## 七、经验总结与答辩要点

### 核心收获
1. **环境问题排查顺序**：先查代理/网络 → 再查依赖缺失 → 再查参数/配置。国内开发绝大多数网络问题源于代理。
2. **算法落地大厂方法论**：数据收集 → 标注 → 预训练模型微调 → 评估 → 部署为服务。用"公开数据集 + 领域语料二次微调"是个人毕设最优路径。
3. **内存问题先看配置**：LDA/c_v 等大内存操作要控制参数，不要盲目加 passes/主题数。
4. **领域适配至关重要**：通用模型（BERT公开数据）迁移到校园场景有明显偏差，必须用领域语料微调。
5. **模型与业务字段对齐**：模型输出要与后端消费字段一致（如 emergency），缺字段会导致功能不生效。

### 可展示的技术亮点（答辩加分）
- 完整实现"匿名发帖 → BERT情感识别 → 高风险预警"闭环
- 真实微调 BERT（F1=0.93，公开数据+校园语料二次微调）
- 真实 LDA 主题模型（4主题话题分流）
- 独立模型服务与业务解耦（BERT :5051、LDA :5052），失败自动降级规则
- 三类角色完整功能 + 积分激励 + 数据看板

### 方法论对照（体现懂行）
- **微调而非从头训练**：用预训练 BERT + 领域数据，省算力、效果好
- **领域数据二次微调**：公开数据打底 + 校园语料精调
- **持续优化/增量更新**：后续可补充紧急语料重训紧急分类头（对应任务书"增量更新"）
- **工程解耦**：模型独立部署、可降级、业务不受模型故障影响
