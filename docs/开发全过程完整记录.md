# 第一部分：开发过程问题与解决报告

> 记录本次毕业设计从环境搭建到功能实现过程中遇到的全部问题、产生原因、解决过程与方法。

## 一、环境搭建阶段

### 问题 1：Python 未真正安装，命令提示符找不到
- **现象**：`python --version` 无反应，`where python` 只找到 Microsoft Store 的占位符（0 字节假程序）。
- **原因**：Windows 的 Microsoft Store 会自动创建一个 `WindowsApps/python.exe` 假程序，用于引导用户去应用商店安装，并非真实 Python。
- **解决**：安装官方 Python 3.13，并勾选 "Add Python to PATH"。实际安装目录在 `C:\Users\<用户>\AppData\Local\Programs\Python\Python313\`。
- **教训**：判断 Python 是否可用不能只看 `where`，要实际运行并看版本；Store 占位符是常见坑。

### 问题 2：MySQL 已安装但服务未启动、命令找不到
- **现象**：`mysql --version` 报 "not recognized"，MySQL 服务状态为 "Stopped"。
- **原因**：MySQL 8.4 已安装（`C:\Program Files\MySQL\MySQL Server 8.4\`），但 bin 目录未加入 PATH，且 Windows 服务未启动。
- **解决**：启动服务 `net start MySQL`（需管理员权限）；将 MySQL bin 目录加入用户级 PATH。
- **注意**：`setx` 写入注册表需要权限，普通终端可能报"注册表访问被拒"，需以管理员权限执行。

### 问题 3：Git 推送 GitHub 失败（network 443 连不上）
- **现象**：`git push` 报 `Failed to connect to github.com port 443`，但 `ping github.com` 能通。
- **原因**：系统开启了代理 `127.0.0.1:7897`（Clash 等），但代理软件未运行，导致 HTTPS 请求被拦截。
- **解决**：确认代理软件启动，或临时关闭系统代理改用直连：
  ```powershell
  Set-ItemProperty -Path 'HKCU:\...\Internet Settings' -Name ProxyEnable -Value 0
  ```
- **教训**：GitHub 推送失败时，先检查系统代理是否开启且代理软件在运行。

### 问题 4：pip 安装包失败（连不上代理端口）
- **原因**：pip 走了系统代理但代理软件未运行。
- **解决**：临时关闭系统代理，或指定国内镜像源：`pip install cryptography -i https://pypi.tuna.tsinghua.edu.cn/simple`。

### 问题 5：PyMySQL 连接 MySQL 8 报错 cryptography 缺失
- **原因**：MySQL 8 默认 `caching_sha2_password` 认证，PyMySQL 需要 `cryptography` 做 RSA 握手。
- **解决**：`pip install cryptography`。

### 问题 6：Python 虚拟环境 pip 引导失败（ensurepip）
- **现象**：`python -m venv` 后 `pip` 缺失，`ensurepip` 报 `PermissionError`。
- **解决**：用系统 Python 的 pip 配合 `--python` 引导到 venv，或在完整权限下执行。

## 二、后端开发阶段

### 问题 7：Flask 配置导入路径错误
- **原因**：`config.py` 在包外，`app/__init__.py` 用了相对导入。
- **解决**：改为绝对导入 `from config import Config`。

### 问题 8：密码哈希过长导致数据库写入失败
- **原因**：scrypt 哈希约 160+ 字符，超过 `VARCHAR(128)`。
- **解决**：password 列改 `VARCHAR(255)`（模型 + 数据库同步）。

### 问题 9：Flask 路由 endpoint 重复注册
- **原因**：改接口时旧函数体残留，路由定义两次。
- **解决**：删除重复函数，确保每路由只注册一次。

### 问题 10：中文内容终端乱码导致测试误判
- **原因**：PowerShell 直接传中文编码错误。
- **解决**：改用 Python `requests` 库（默认 UTF-8）发送。

## 三、前端开发阶段

### 问题 11：npm 脚本被 PowerShell 拦截
- **解决**：用 `npm.cmd` 代替 `npm`。

### 问题 12：echarts 打包体积过大警告
- **解决**：不影响功能，可忽略。

## 四、BERT 情感分析阶段

### 问题 13：transformers 5.x 参数名变更
- **现象**：`evaluation_strategy` 报错、`logging_dir` 报错。
- **解决**：改用 `eval_strategy="epoch"`，移除 `logging_dir`；安装 `accelerate`。

### 问题 14：BERT 预训练模型加载警告（missing/unexpected keys）
- **原因**：预训练是 MLM 头，转分类任务时分类头参数新建（MISSING）；LayerNorm 命名差异（UNEXPECTED）。
- **解决**：正常现象，可忽略。

### 问题 15：推理服务缺 flask 模块
- **原因**：ML 独立环境与后端隔离。
- **解决**：ML 环境单独 `pip install flask`。

### 问题 16：BERT 对校园文本判定偏差（关键）
- **现象**：公开数据集（ChnSentiCorp，商业评论）训练的模型，把"考研通过今天开心幸福"误判为负向。
- **原因**：公开数据集是商品评论情感，没有校园场景语料，不懂"考研上岸""期末考试"等。
- **解决**：AI 生成校园语料（学业/情感/求职/生活 + 高危）二次微调 BERT，得到"校园微调版"。
- **教训**：通用/公开数据集迁移到特定领域有明显偏差，需领域语料二次微调。

### 问题 17：BERT 推理后缺少紧急程度字段，预警不触发
- **现象**：发帖后 `emergency=None`、`warning=False`，高危内容没预警。
- **原因**：BERT 只输出正/负分类，推理服务没返回紧急字段。
- **解决**：在推理服务增加 `compute_emergency`（BERT 情感 + 高危关键词规则组合），命中自伤类词判紧急。
- **教训**：模型输出与业务字段要对齐；紧急程度可作为独立任务或规则补充。

### 问题 18：Python 3.13 下 torch/深度学习库兼容性
- **应对**：选用兼容当前 Python 版本的 torch（2.11.0+cu128），确认 GPU CUDA 匹配（RTX 5070 Ti，CUDA 13.4，装 cu128 版）。

## 五、LDA 主题模型阶段

### 问题 19：LDA 训练爆内存
- **原因**：`CoherenceModel` + `c_v` 共现统计开销大；循环里对 2~6 主题各训一次；`passes=20` + `alpha/eta="auto"`。
- **关键结论**：本不该爆（有 20GB 内存，60条短文本只需几百 MB），是脚本配置激进。
- **解决**：内存安全配置——放弃 c_v，固定 4 主题，passes=8，去掉 alpha/eta="auto"。训练秒级完成。

### 问题 20：LDA 推理返回 float32 无法 JSON 序列化
- **解决**：概率转 Python `float()`：`{str(t): float(round(p,4)) for t,p in dist}`。

### 问题 21：LDA 对某些短文本概率为 0、归类默认
- **原因**：语料小（60条），部分词不在词典。
- **解决**：可接受（有默认板块兜底）。

## 六、模型与文件管理

### 问题 22：模型权重误加入 Git 仓库
- **原因**：`.gitignore` 只忽略 `*.pt/*.pth/*.bin/*.onnx`，未覆盖 `.safetensors`（transformers 5.x 默认格式）。
- **解决**：`git reset` 取消暂存；`.gitignore` 增加 `*.safetensors`、`ml/data/models/`、`ml/data/*/processed/`。

## 阶段四：多任务 BERT 大模型式（3e0ed4a）

### 调整 8：多任务 BERT（三头共享编码）（3e0ed4a）
- **架构**：共享 BERT 编码层 + 三输出头（情感 3 分类 / 紧急 3 分类 / 分值回归 -10~+10）。
- 联合训练，损失 = loss_sentiment + loss_emergency + 0.5 × loss_valence。
- **关键设计**：类别不均衡上采样 + 权重；高危规则兜底。

### 调整 9：反讽/强撑语料微调（0d3508a）
- 加入反讽（表面积极实则消极）与"强撑/求救"语料二次微调。
- **效果**：反讽正确判负向；求救信号（"想死"）稳定判紧急。

## 阶段四半：公开数据集初期训练与被否决的方案（重要坎坷）

### 尝试 A：公开数据集直接训练（ChnSentiCorp 等，上万条）
- 公开情感数据集直接微调 BERT，规模上万余条。
- **问题**：通用评论/商品舆情为主，校园/口语/高危覆盖不足；负向样本类型有限且非心理类。

### 尝试 B：cpsdd 大数据量训练（未被采纳）
- 引入 **cpsdd 真实心理倾诉数据集，规模达 70005 条**。
- **结果（被否决）**：
  - **负面样本压倒性**：cpsdd 是心理咨询场景，负向占绝大多数，正向寥寥无几。
  - **类别严重失衡**：模型陷入"倾向判负"偏差，**正向表达被负向淹没**。
  - **致命缺陷**：出现"**我爱你被误判为负向**"——绝对正向词被负向语料淹没。
  - **明确要求**：各类语料要均衡完整，不要出现日常高频词没见过、绝对正向词被判负、负向特别多正向特别少。
  - 因此，**单纯堆砌 cpsdd 大数据的方案被否决**，转向"类别均衡 + 扩充正向/中性语料"。
- **意义**：这一被否决阶段直接催生了后续"语料均衡训练"和"40000 条均衡语料"，是模型优化的**转折点**。

## 阶段五：语料均衡与精确分值（2b656c3）

### 调整 10：引入真实心理倾诉数据集 + 人工语料（均衡方向）
- 引入 cpsdd 真实数据提取 + **人工语料各类约 2000 条**（打破负向压倒，补充正向/中性）。
- **类别均衡训练**（上采样 + 类别权重）。
- eval_loss 降至 **0.40**。
- **效果（分值梯度精准）**：轻度抱怨 -3~-4；中度负面 -5~-8；高危 -9.2；中性 0。

## 阶段六：扩大语料至 40000 条且各等级均衡（c35a81b）

### 调整 11：语料扩充至 40000 条
- **问题**：训练集仍负向压倒（负 8113、正 1806、中 1808），正向类型单一（多为成就型），"我爱你""好想你"等绝对正向词仍被误判负向。
- **方案**：
  - 扩充语料至 **40000 条**；**各等级均衡**（正/负/中性各约 1/3，彻底解决负向压倒）。
  - 引入大量**日常高频情感语料**：爱意/思念（我爱你、好想你、喜欢你）、温馨/感恩（被关心、谢谢你）、轻松/娱乐（打游戏、看剧、追星）、成就/喜悦（上岸、获奖）、撒娇/亲昵（讨厌你好坏、我心疼你）。
  - 重训多任务 BERT。
- **效果**：绝对正向词误判修复，测试准确率 **28/28**。

## 阶段七：置信度兜底（7e08a2f）

### 调整 12：置信度兜底规则
- **问题**：语料扩充后仍有生僻/无上下文内容被误判。
- **方案**：读取情感/紧急分类**最高概率（置信度）**；情感 < 0.60 → 中性，紧急 < 0.55 → 正常（模型没把握时归中性/正常）。补充 **2460 条超短中性/无谓陈述语料**，重训至 **42460 条**。
- **效果**："我是一个人类"不再误判负向关注。

### 调整 13：补充超短中性语料
- 新增脚本 `add_short_neutral.py`，补充超短中性/无谓陈述/应答语料，使模型学会这类是中性。

## 阶段八：预处理增强（cde388c）

### 调整 14：情感推理预处理增强（5 层防线）
- **问题**：纯符号（！！！###）、重复刷屏（哈哈哈×40）、学术描述、无情绪陈述被误判负向甚至预警。
- **方案**（送入 BERT 前预处理）：
  1. 纯符号/无意义（有效字母<3）→ 中性。
  2. 重复刷屏（大量重复）→ 中性。
  3. 学术/专业陈述（含学术词且无情绪词）→ 中性。
  4. 客观陈述/日程（len≥8、含客观词、无情绪/反问/感叹/网络梗）→ 中性。
  5. 置信度兜底（没把握）→ 中性。
- **关键约束（避免误伤真实情绪）**：
  - 反问句（？！）、网络梗（麻了/栓Q/起飞/破防）**不判中性**，避免"梦想成真要起飞了""我到底做错什么"误判中性。
  - 高危词（想死/自杀）**永不判中性**，保证预警不遗漏。
- **效果**：纯符号/刷屏/学术/客观陈述→中性；真实情绪保留；真高危仍判紧急。

## 阶段九：大模型二次筛选（a297dd3）

### 调整 15：接入 DeepSeek 大模型二次筛选
- **动机**：预处理解决"无情绪内容"误判，但仍有"有文字、无情绪词却仍被 BERT 误判"的边缘样本。引入大模型对**极少数边缘负向样本**二次复核，防止误判，不干扰正常 BERT 判断。
- **触发条件**（满足其一才调，严格控制量）：① BERT 判负向且紧急=关注/紧急；② BERT 判负向且置信度 < 0.90。
- **大模型判断**：DeepSeek 只回答「负向/中性/正向」。负向→保留（高危确认）；中性/正向→纠正（误判救回），紧急归正常。
- **API key 安全**：key 从环境变量 `DEEPSEEK_API_KEY` 读取，不硬编码、不进 git。
- **效果**："听说那个同学最近不太好"（误判负向）→ 大模型判中性纠正；"真的想死"→ 大模型确认负向仍判紧急。

## 阶段十：纠错样本知识库（1d4a66e）

### 调整 16：纠错样本知识库相似匹配（方案3）
- **动机**：避免"每多一个纠错样本就重训一次全量 40000+ 条"，把大模型纠正过的样本存入**独立纠错文件**，通过**相似匹配**让模型"理解"知识。
- **方案**：
  - 纠错样本存入 `llm_corrections.jsonl`。
  - 推理时 BERT 判负向+触发条件后，**优先查纠错样本库**：用字符重合度（阈值≥0.75）判断相似，命中直接采用已纠正标签；未命中才调 DeepSeek 复核。
  - **不重训全量语料**，少量纠错样本通过相似匹配生效。
- **效果**："听说那个同学最近不太好"及变体→命中纠错库判中性；"我期末压力大很焦虑"（不相似）→大模型确认保留负向关注；"我真的想死"→保留紧急。

# 最终架构小结

## 推理流程（server.py，端口 5051）
```
输入文本
  ↓
预处理（5层防线）：纯符号 / 刷屏 / 学术 / 客观陈述 / 置信度
  ↓（未判中性则继续）
BERT 多任务模型
  → 情感(3分类)  紧急(3分类)  分值(-10~+10)
  ↓
若判负向 且 (紧急=关注/紧急 或 置信度<0.90)：
   → 查纠错样本库(相似匹配) → 命中：直接用已纠正标签
                             → 未命中：调 DeepSeek 大模型复核
                                     → 负向：保留(高危确认) / 中性·正向：纠正+写回样本库
  ↓
分级校准(calibrate_valence) → 输出
```

## 模型架构（model.py）
- 共享 BERT 编码层。
- 三头输出：情感倾向（3分类）、紧急程度（3分类）、分值回归（-10~+10）。
- 联合训练，损失 = loss_sentiment + loss_emergency + 0.5 × loss_valence。

## 关键配置（train_multitask.py）
- epochs = 3，batch = 16，learning_rate = 2e-5，eval_strategy = "epoch"。

# 经验总结与答辩要点

## 核心收获
1. **环境问题排查顺序**：先查代理/网络 → 再查依赖缺失 → 再查参数/配置。国内网络问题多源于代理。
2. **算法落地方法论**：数据收集 → 标注 → 预训练微调 → 评估 → 部署。用"公开数据集 + 领域语料二次微调"是个人毕设最优路径。
3. **内存问题先看配置**：LDA/c_v 等大内存操作要控制参数。
4. **领域适配至关重要**：通用模型迁移到校园场景有明显偏差，必须用领域语料微调。
5. **模型与业务字段对齐**：模型输出要与后端消费字段一致（如 emergency）。
6. **语料均衡是模型精度关键**：负向压倒会导致正向误判，均衡语料是解决"绝对正向词误判"的核心。

## 可展示的技术亮点（答辩加分）
- 完整实现"匿名发帖 → BERT 情感识别 → 高风险预警"闭环。
- 真实微调 BERT（F1=0.93，公开数据 + 校园语料二次微调）。
- 真实 LDA 主题模型（4 主题话题分流）。
- 独立模型服务与业务解耦（BERT :5051、LDA :5052），失败自动降级规则。
- 多任务 BERT（情感/紧急/分值三头）+ 语料均衡优化 + 大模型二次筛选 + 纠错知识库。
- 三类角色完整功能 + 积分激励 + 数据看板。

## 方法论对照（体现懂行）
- **微调而非从头训练**：预训练 BERT + 领域数据，省算力、效果好。
- **领域数据二次微调**：公开数据打底 + 校园语料精调。
- **持续优化/增量更新**：纠错知识库通过相似匹配增量学习，不重训全量。
- **工程解耦**：模型独立部署、可降级、业务不受模型故障影响。
- **多模型结合**：BERT（情绪主体）+ 规则（高危兜底）+ 大模型（边缘复核）多策略融合。
